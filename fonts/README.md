`android-test.ttf` is an original geometric font fixture generated by
`generate-android-test-font.py`. It has
rectangles, one quadratic curve and an empty space. It is included only in unit
tests, never in the Android APK. Regenerate with Python and `fonttools==4.59.1`.

The Android application reads fonts already installed in `/system/fonts` or
`/product/fonts`. No Android or Apple font assets are redistributed here.

`android-cff2-test.ttc` is another original geometric test fixture, generated by
`generate-android-cff2-test-font.py` with the same pinned fonttools version. Its
one-face collection contains a CFF2 rectangle and cubic curve mapped to Hangul
`ㄱ` and `가`, an empty ideographic space, and a weight axis. It verifies visible
A8 fallback outlines, since fontdue recognizes
the characters even when ttf-parser's `variable-fonts` feature is disabled and
their outlines are empty. This fixture is also excluded from the APK.

Android 15 can package a variable CFF2 collection under the filename
`NotoSansCJK-Regular.ttc`; see the `use_var_font` choice in the
[AOSP font build definition](https://android.googlesource.com/platform/external/noto-fonts/+/refs/heads/android15-release/notosanscjk/Android.bp).
The Android dependency enables the parser feature. Primary monospace glyphs use
fontdue; fallbacks retain at most two font files of 32 MiB each and rasterize only
requested outlines with `ab_glyph_rasterizer`. The old fallback is evicted before
reading a third file. A raster is bounded by the 1024×1024 atlas dimensions before
allocation; its temporary coverage buffer uses about 4 MiB at that maximum.
No production font is bundled.

To reproduce the eager/per-glyph memory comparison on the host without building
the application, save a copy of the device's system CJK font outside this repo
and build the small probe in a temporary directory:

```sh
font_probe_root="$PWD"
font_probe_dir="$(mktemp -d)"
cat > "$font_probe_dir/Cargo.toml" <<EOF
[package]
name = "kokuban-font-probe"
version = "0.0.0"
edition = "2021"
[[bin]]
name = "kokuban-font-probe"
path = "$font_probe_root/fonts/probe-android-fallback.rs"
[dependencies]
fontdue = { version = "=0.9.3", default-features = false, features = ["std", "simd"] }
ttf-parser = { version = "=0.21.1", default-features = false, features = ["variable-fonts"] }
ab_glyph_rasterizer = "=0.1.10"
[profile.release]
opt-level = 1
debug = 0
EOF
rustup run 1.94.1 cargo build --offline --release --manifest-path "$font_probe_dir/Cargo.toml"
# macOS uses time -l; on Linux use time -v for peak RSS.
/usr/bin/time -l "$font_probe_dir/target/release/kokuban-font-probe" eager /path/to/NotoSansCJK-Regular.ttc
/usr/bin/time -l "$font_probe_dir/target/release/kokuban-font-probe" lazy /path/to/NotoSansCJK-Regular.ttc
```

On 2026-09-06, Rust 1.94.1/macOS ARM64, the Android 15 AOSP variable font
(`NotoSansCJK-wght-400-900.otf.ttc`, 32,355,424 bytes, SHA256
`3e7e5afaac2c6d872592d76abedac03a51c6f0fc42d11e311ff2816a6c368afe`)
produced visible 22×19 `ㄱ` and 31×34 `가` glyphs at 36.75 px. A focused probe
compiled with opt-level=1 measured peak RSS **351,305,728 bytes eager** and
**34,062,336 bytes per glyph**; loading took 203 ms and 3 ms respectively.
These are single host-process observations, not Android PSS or performance gates.
The earlier parser without CFF2 support used 40,501,248 bytes but produced zero
coverage for both glyphs. The probe intentionally includes CFF2 support in both
modes so memory can be compared while preserving visible output.
